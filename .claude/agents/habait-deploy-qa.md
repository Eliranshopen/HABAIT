- **Browser paint-proof recipe (CP-27 — the law "a curl 200 does not prove a browser will paint", warden, gate #20, 2026-07-14, operationalized).** `WebFetch`/`curl` is curl-class evidence and does NOT satisfy this step. For every surface a ship claims renders: (1) headless Chrome via `playwright-core` (installed under `Projects/Habait/tools/appdeps/`; ready scripts in `Projects/Habait/tools/deploy-vercel/qa/*.cjs`), driven from `Bash`, in a fresh **logged-out** context (no cookies) unless the surface is gated, in which case one logged-out AND one logged-in pass; (2) navigate to the DEPLOYED URL, never localhost; (3) assert the **real network request the feature depends on** fired and returned 200 with the right content-type — a `Range` `.mp4` request for video (the landing's cine clips are the proven case), a panorama or `.glb` fetch for the tour and dollhouse, tile/glyph `.pbf` fetches for a map — not merely the document status; (4) assert the DOM painted: the element is visible with a non-zero bounding box, a canvas is non-blank by pixel sample, and the console holds no error; (5) assert CONTENT, not just paint — a raw 401 JSON body IS a paint of the wrong thing (the 2026-07-16 R-D4-MAP lesson); (6) save the screenshot as lossless WebP into the board's own `logs/` folder (`development/tasks/<board>/logs/`; `qa-evidence/` and `docs/governance/RETENTION.md` were not transferred) and cite it in the QA report. The `mcp__claude-in-chrome__*` lane may be used ADDITIVELY where it is registered (per-machine `~/.claude.json`, Eliran's act); the Bash recipe stays the fallback. The old app's precedent report `Habait/MVP/docs/qa-report-showcase-final.md` was not transferred.
- **QA matrix** (before every "it's ready"): the board's QA cards (root §8.9) — each page the board touched × {Chrome, Edge} × {desktop, 390px} on the DEPLOYED `habait-flow` URL, not just localhost: the live result first, the deployed site after Eliran's deploy go.
