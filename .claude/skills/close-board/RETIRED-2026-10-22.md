## Step 2 — THE CAPPED SHIP SUMMARY IN THE BOARD README

The convention (`development/tasks/CLAUDE.md`, `rnd-reorg` T19; **forward-only**): a board's
closing/ship summary — wherever it lands in that board's own `README.md` — caps at **a few lines**:

1. the ship state,
2. the commit hash(es), citable per step 1,
3. a link to the `memory/runs/` entry, which is where the narrative belongs.

⛔ **Forward-only means forward-only.** The **21 of 39** boards that already carry a full prose retelling
in their own README stay untouched. This cap governs new closing summaries; it is not a licence to
rewrite finished boards.

⭐ **Both halves or neither:** a citation with no link back to the fuller record is unverifiable in
practice; a link with no citable hash is unverifiable in principle.


## Step 7 — THE `SHIP-LEDGER.md` ROW, IF THE BOARD SHIPPED AND THE ROW IS MISSING

**Three gates before you write anything here — most boards fail at least one, legitimately:**

1. **Scope.** The ledger tracks the **app repo** (`<github-org>/<app-repo>`), *"because that is the only
   tree that deploys."* ⛔ A harness-root board has **no** ship row. Skip with that reason.
2. **Backfill boundary.** The ledger **opens at 2026-08-17 and is not retro-filled.** An older ship stays
   authoritative in `memory/runs/` + root `CLAUDE.md` §9.
3. **Already there?** `grep -c "<merge-hash>" docs/governance/SHIP-LEDGER.md` — never file a duplicate row.

If all three pass, add the row newest-first at the top of §1, and honour the file's own mechanics:

- **Sourcing is SPLIT:** `Date · Board · Plan · Contract · Gate · QA · Spend` come from the gate memo /
  QA report / board; **`Merge commit` · `Live-verified` · `Rollback` come from the `memory/runs/` entry +
  `git log origin/main`.** Only git records what shipped.
- ⛔ **An empty `Board` / `Plan` / `Gate` cell is LEGITIMATE, not a gap** — write `⛔ none`.
- **`Rollback`** is `git revert -m 1 <merge>` **only for a real merge commit**; a fast-forward has no
  mainline to pick, so it is a plain `git revert <hash>`. State which.
- ⭐ **Also prepend the evidence path** to the "**Evidence paths, in the same order**" block directly
  under the table. It is **positionally coupled** to the rows — nothing in the schema says so, it is only
  visible by reading the file — and a row added without its evidence line silently desynchronises every
  path beneath it.

```
SKIP (step 7 ship-ledger row): harness-root board — the ledger's scope is the app repo (line 18)
SKIP (step 7 ship-ledger row): docs/governance/SHIP-LEDGER.md not present
```

## Step 9 — GARDEN: shelve, rotate, regenerate, verify STRICT (added 2026-09-08)

1. **Shelve the one-off personas this board minted** → `memory/agents/_ephemeral/<name>.md`; ⛔ never delete a
   memory file (`/plan-to-tasks` Step 7 is the label-never-move counterpart and owns the definition side).
2. **Rotate any live `project/` / `agents/` / `listings/` file over 200 KB** onto its month shelf, with the
   archive-index block written into the live file and every `memory/INDEX.md` line repointed **in the same commit**.
3. **Regenerate both generated files:** `node .claude/skills/sync-context/generate-hot.mjs`, then
   `node .claude/skills/sync-context/generate-topics.mjs`.
4. **Verify:** `node .claude/skills/sync-context/verify-memory.mjs --strict` must print `CLEAN`.
   ⛔ **Strict FAILS the close here** (R-9) — a post-cutoff `memory/INDEX.md` line over 400 characters, or a live
   `memory/agents/<name>.md` over 200 KB, stops the close until it is fixed. Ad-hoc runs elsewhere stay warn-only.

Pointer: the shelf layout and the archive-index block format are `memory/README.md`'s, not this skill's.

## Step 10 — PROMOTE: the earned-twice trigger (added 2026-09-08)

Scan the `project/` facts step 8 wrote or refreshed. A fact **earned twice** — proved by two independent
boards, runs or measurements — is **PROPOSED** for promotion to a law; ⛔ it is never self-promoted.
- Write each proposal into the step-5 close run entry **and** into the closing summary, as four things: the
  fact, its two pieces of evidence, the card or register it would land in, and its lint / hook / skill step —
  or the word `UNENFORCED`, stated rather than implied.
- ⛔ **Anything touching legal, cost, style or the section-8 conventions is `FOR-ELIRAN`** — proposed in the
  summary, ruled by Eliran, never applied by this run.
- A fact earned once stays a `project/` entry. Say so plainly; do not pad the proposal list to look thorough.

Pointer: `memory/README.md` (**chokepoints, not cron**) owns the promotion contract this step executes.
Source: harness upgrade plan (`docs/harness-upgrade-plan.md`), wave 3.
