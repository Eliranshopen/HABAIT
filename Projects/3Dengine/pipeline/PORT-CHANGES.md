# Changes to the brought-in pipeline

Everything under this folder was brought from git commit a63494a as it is, and the closing test of milestone 0.1 compares every file with that commit, blob for blob. A file that the engine had to change is listed here, with what was changed and why, and with the git blob id of its changed form: the test compares a listed file with THAT id, so a listed file can differ from its source only in the way that is written here. A file path and its blob id are written in backticks, the path relative to this folder; nothing else in this document is in backticks. After another change of a listed file, write its new id (git hash-object on the file) and say what changed.

| File | Changed | Git blob id of the changed file | What and why |
|---|---|---|---|
| `Habait/tour360/tools/auto-trace.mjs` | 2026-11-18, milestones 1.2 and 1.4 | `c55bfe16f9dce58f9f454e7c9805bdacf8cab358` | TWO changes. (1) Milestone 1.2: one line (and a two-line comment above it), in the function that makes a vision call: when the OpenRouter key is present, the request now carries it in the Authorization header. Before, the request went to OpenRouter with no key and was refused (HTTP 401, nothing billed): the transport passes a request straight through when that key exists, and this tool was the only caller that did not send the header. Until 2026-11-17 the keys file held only the fal key, so every reading went through fal's router, where the transport adds its own header; that is why the measured runs never met it. The fal route is unchanged. Found by the paid reading of milestone 1.2; proven by part 3 of the engine's closing test for that milestone, with a recording fetch and planted keys, at no cost. (2) Milestone 1.4: one line, where the tool builds the settings of a plan: the date it writes into the plan (plan_meta.trace_date) can be given with the flag --trace-date; without the flag it writes the day of the run, as before. The tool wrote the day into every plan, so the same reading traced on another day gave other bytes of the plan file; the engine now hands it the date the reading was made, and the same reading gives the same plan (contract 1.4, section 3). Proven by the pinned hash of the 846 plan in the engine's stage tests. Against the source, both changes together: 4 lines inserted, 2 removed. |
