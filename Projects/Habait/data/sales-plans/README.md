## 1. מה שמים ואיפה

```
sales-plans/
├── README.md                      ← הקובץ הזה
├── LABELING-GUIDE-he.md           ← איך מייצרים/מתקנים plan.json ומה כלל הקבלה
├── collection-plan-he.md          ← מאיפה מביאים תכניות, כמה, ואיזה מידע חובה

├── templates/meta.template.json   ← תבנית meta.json
├── <developer>/<project>/<unit-or-type>/   ← תיקייה לכל תכנית (סעיף 2)
```

**הכלל הפשוט ביותר:** קיבלת תכנית → שמור ב-`_inbox/` בשם המקורי. אחת לשבוע (או מיד, אם יש 10 דקות) ממיינים לתיקייה לפי סעיף 2 ומוסיפים שורה ל-`index.csv`. תכנית ב-`_inbox` לא נספרת ביעד.

## 2. מבנה תיקייה לתכנית

```
<developer>/<project>/<unit-or-type>/
├── source.pdf  |  source.dwg  |  source.dxf  |  source.ifc    ← הקובץ המקורי, שם קבוע
├── pages/p0-sheet-150dpi.png, p0-apartment-crop.png, ...      ← רנדר של הדפים (150 dpi ל-VLM, 288 dpi לטרייסר)
├── meta.json        ← מה כתוב על הגיליון: יזם, פרויקט, דירה, קומה, שטחים, מידות מודפסות, חדרים, זכויות (templates/meta.template.json)
├── plan.json        ← הגאומטריה (סכמת plan.json, ס"מ, y כלפי מטה). קיים רק כשהתכנית תויגה
└── corrections.json ← מה אדם תיקן אחרי המכונה (זה הדאטה לאימון)
```

**שמות תיקיות:** אותיות לטיניות קטנות, מקפים, בלי רווחים ובלי עברית (עברית נשארת בתוך הקבצים):
- יזם: `israel-canada`, `azorim`, `tidhar`, `shikun-binui`
- פרויקט: `rainbow-tel-aviv`, `park-tzameret-b`
- דירה ספציפית: `unit-846`; טיפוס מתוך פרוספקט: `type-l`, `type-4r-mirrored`; קומה שלמה: `floor-16`

**שם קובץ המקור** תמיד `source.<ext>`. השם המקורי של הקובץ נשמר ב-`meta.json` → `drawing.original_filename` (אם רוצים).

## 3. `index.csv`

שורה אחת לכל תיקיית תכנית. עמודות:

| עמודה | ערכים | הערה |
|---|---|---|
| `id` | `<developer-short>-<project-short>-<unit>` | למשל `ic-rainbow-846`. יציב; לא משנים |
| `developer`, `project`, `city` | טקסט חופשי (עברית בסדר) | כמו שכתוב על הגיליון |
| `unit` | מספר דירה או ריק | לטיפוס מפרוספקט: ריק |
| `type_mark` | אות/קוד הטיפוס מהגיליון | `L`, `A1`, ... |
| `rooms` | מספר חדרים לפי המפרט | 3, 4, 5 (חצי: 3.5) |
| `area_m2` | שטח הדירה מהטבלה שעל הגיליון | בלי מרפסת |
| `scale` | `1:50`, `1:100`, `none` | |
| `source_kind` | `raster` / `vector` / `dwg` / `ifc` | PDF שהטקסט בו ניתן לסימון = `vector` |
| `has_mamad` | `yes` / `no` / `unknown` | ממ"ד בתוך הדירה. ממ"ק קומתי = `no` + הערה |
| `mirrored` | `yes` / `no` / `unknown` | `yes` רק אם הגיליון אומר "הפוכה"/"מראה"/"mirror" |
| `labeled` | `yes` / `no` | יש `plan.json` שעבר את כלל הקבלה (LABELING-GUIDE) |
| `notes` | חופשי | קומה, תאריך גיליון, מצב זכויות, מוזרויות |

ערכים עם פסיק עוטפים במרכאות כפולות (כמו בשורה של 846).

## 4. פרטיות וזכויות: מה מותר לשמור כאן

1. **תכנית של דירה שנמכרה לרוכש אמיתי היא מסמך חוזי חסוי** (נספח לחוזה המכר). שומרים אותה רק אם: (א) היא יצאה מהארכיון של החברה בפרויקט ש-Habait משווקת/שיווקה, או (ב) היזם נתן רשות. לא מהאינטרנט, לא מרוכשים, לא מקבוצות וואטסאפ.
2. **לפני שהקובץ נכנס לתיקייה: מסירים פרטי רוכש.** שם, ת"ז, חתימות, מחיר, לוח תשלומים, חותמת "נספח לחוזה של ...". אם אי אפשר להסיר מהמקור (סריקה), מייצאים רק את עמוד התכנית לתוך `source.pdf` ומסמנים ב-`meta.json` → `rights.redacted: true`. את הקובץ הלא-מצונזר **לא** שומרים כאן.
3. **עדיפות לתכניות טיפוס** (מהפרוספקט / מחוברת המכירות): הן מיועדות להפצה ממילא ואין בהן רוכש. 846 הוא דוגמה לתכנית דירה ספציפית שקיבלנו משותף.
4. **כל תכנית מקבלת `rights_state`** (`own` / `licensed` / `partner-supplied` / `unrecorded`) ב-`meta.json` → `rights`. `unrecorded` = לא יודעים מי אישר מה → מותר לניסוי פנימי בלבד, אסור להראות לאף אחד מחוץ לחברה, ואסור לאימון (SCHEMA.md, A8-13).
5. **אימון מודלים:** רק תכניות שסומנו במפורש שמותר (`rights_note` מכיל "training ok" ומי אישר). ברירת המחדל: לא.
6. **לא מעלים** תכניות לשירותי ענן חיצוניים (כולל API של מודלים) בלי שזה מכוסה ברשות שניתנה. לניסויי VLM בתשלום: קודם לבדוק שה-`rights_state` מאפשר, ולהעדיף את התכניות של הפרויקטים של Habait עצמה.
7. **זכויות יוצרים של האדריכל** בשרטוט: שימוש פנימי להפקת הדמיות ליזם שהזמין אותן הוא במסגרת השימוש הרגיל; פרסום השרטוט עצמו או שימוש לאימון דורש בדיקה (ראו `legal/lawyer-checklist-he.md`, שאלה 7).

## 5. סדר עבודה לתכנית חדשה (10–20 דקות בלי תיוג, +20–60 דקות עם)

1. `_inbox/` → תיקייה לפי סעיף 2, `source.<ext>`.
2. רנדר דפים ל-`pages/` (ב-PowerShell/Git Bash):
   `PYTHONIOENCODING=utf-8 C:/RnD/Projects/Habait/tools/habait-venv/Scripts/python.exe -I -c "import pymupdf,sys; d=pymupdf.open(sys.argv[1]); [p.get_pixmap(dpi=150).save(f'pages/p{i}-sheet-150dpi.png') for i,p in enumerate(d)]" source.pdf`
3. `meta.json` מהתבנית: ממלאים ידנית את מה שכתוב על הגיליון (זה 5 דקות ושווה זהב: המידות המודפסות הן מנגנון האימות של כל השאר).
4. שורה ב-`index.csv` עם `labeled=no`.
5. תיוג (`plan.json`) לפי `LABELING-GUIDE-he.md`, דרך מסך התיקון (A2) כשיהיה, או דרך הטרייסר הקיים. כשעובר את כלל הקבלה: `labeled=yes`.
6. אם מודל קרא את התכנית (VLM): הפלט נשמר ב-`eval/<date>/inputs/` ונמדד ב-`tools/eval_intake.py` (ראו `eval/README.md`).
