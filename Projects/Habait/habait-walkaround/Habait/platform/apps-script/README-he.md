# מדידה ולידים: מה אלירן עושה פעם אחת (כרטיס 24, D2)

היום **שום דבר לא יוצא מהמכשיר של הרוכש**: האירועים נכתבים רק לקובץ מקומי (`_local/events.jsonl`), והלידים רק ל-console. שלושת הצעדים למטה מדליקים את הצד השלישי. כל אחד מהם עצמאי, ואפשר לעשות רק חלק.

**לפני שמדליקים מפתח אמיתי:** בדיקת `qa-reviewer` (הקשר נקי) על רשימת השדות שיוצאים (בסוף הקובץ). זה תנאי של הכרטיס (T2).

## 1. PostHog (אירועים, חינם עד מיליון בחודש)

1. נכנסים ל-https://posthog.com → **Get started - free** → נרשמים עם office@habait.ai.
2. בוחרים אזור **US Cloud** (או EU Cloud; אם EU, להגיד לנו, כי הכתובת משתנה ל-`https://eu.i.posthog.com`).
3. שם הארגון: Habait. שם הפרויקט: `habait-platform`. כשהוא שואל מה מתקינים: **Skip** (אנחנו כבר מחזיקים את ה-SDK אצלנו).
4. **Settings → Project → General:** מעתיקים את **Project API key** (מתחיל ב-`phc_`). המפתח הזה ציבורי מטבעו (הוא יושב בדף), ואפשר לשלוח אותו בצ'אט של habait-4b.
5. **Settings → Project → General → IP data capture:** מסמנים **Discard client IP data** (כך כתובת ה-IP של הרוכש לא נשמרת).
6. **Settings → Project → Replay:** לוודא ש-Session replay **כבוי** (אנחנו לא מקליטים מסך).
7. לדשבורד בלבד (רשות): **Settings → User → Personal API keys → Create**, היקף `query:read` בלבד. המפתח הזה (`phx_`) **סודי**: לא בצ'אט ולא בקובץ. מדביקים אותו רק בדשבורד, תחת "הגדרות מתקדמות", יחד עם ה-Project ID (מספר, מופיע ב-Settings → Project).

מה 4b עושה עם ה-`phc_`: ממלא את `posthog_key` בבלוק `"analytics"` שכבר קיים ב-`project.json` של הפרויקט (הסכמה: `contracts/project.schema.json`). `flow.js` ו-`apartment.js` כבר מעבירים את הבלוק ל-`initAnalytics({ ..., config: P.analytics })`. כל עוד `posthog_key` ריק, שום דבר לא יוצא. בגרסה העצמאית (`tools/build_zip.mjs`) קובצי ה-PostHog (`posthog-adapter.js` וה-SDK) מועתקים רק כשיש מפתח, ואחרי כל שינוי במפתח **בונים את ה-dist מחדש**. עותק ישן של `analytics.js` שולח שדות שאסור לו לשלוח.

## 2. Google Sheet ללידים (Apps Script, חינם)

1. https://sheets.new (מחובר ל-office@habait.ai) → שם הקובץ: `Habait לידים`.
2. בתפריט: **Extensions → Apps Script**. מוחקים את מה שיש בעורך, ומדביקים את כל התוכן של `lead-to-sheet.gs` (הקובץ שליד הקובץ הזה). שומרים (Ctrl+S).
3. **Deploy → New deployment** → גלגל השיניים → **Web app**.
   - Description: `habait leads v1`
   - Execute as: **Me**
   - Who has access: **Anyone** (הטופס בדף שולח בלי התחברות; הסקריפט כותב רק שורה חדשה ולא קורא כלום מהגיליון)
4. **Deploy** → מאשרים הרשאות (Google יזהיר "unverified app": Advanced → Go to project → Allow; זה הסקריפט שלך).
5. מעתיקים את ה-**Web app URL** (מסתיים ב-`/exec`) ושולחים בצ'אט של habait-4b. הוא נכנס ל-`project.json → leads.webhook_url` (או `sheet_endpoint`).
6. בדיקה: פותחים את ה-URL בדפדפן. צריך לראות `{"ok":true,"service":"habait-lead-to-sheet","version":2}`.
7. **סיסמה משותפת (מומלץ):** בעורך של Apps Script: **Project Settings** (גלגל השיניים משמאל) → **Script properties** → **Add script property**. שם: `LEAD_SECRET`. ערך: מחרוזת אקראית של 16 עד 120 תווים, אותיות/ספרות/`_.-` (למשל מ-https://www.random.org/strings). את אותו ערך שולחים לנו, והוא נכנס ל-`project.json → analytics.lead_secret`. מרגע שהוגדר, ליד בלי הסיסמה נדחה (`auth`). הסיסמה יושבת בדף, ולכן היא עוצרת בוטים ושליחות אקראיות, לא תוקף שמתאמץ. ההגבלות שלמטה הן ההגנה העיקרית.
8. **חובה: בדיקה ידנית של שורה אחת לפני שמפרסמים את הקישור.** פותחים את דף הדירה עם ה-URL החדש, ממלאים טופס עם הטלפון `0501234567` ומסמנים הסכמה. בגיליון בודקים ש:
   - העמודה `phone` מציגה **`0501234567`** עם האפס, בלי גרש גלוי, ומיושרת לשמאל כמו טקסט.
   - שם שמתחיל ב-`=` (למשל `=1+1`) מוצג כטקסט, לא כתוצאה של נוסחה.
   - העמודה `units_viewed` מציגה את הדירות שנצפו.

   אי אפשר לבדוק את זה אצלנו בלי Google: הטסט מריץ את הסקריפט מול גיליון מדומה.

הגיליון מקבל לשונית `Leads` עם העמודות: מתי התקבל, מתי נשלח, פרויקט, דירה, קומה, שם, טלפון (טקסט), הסכמה, הדירות שנצפו, מקור (src), session, שפה, מחיר, סטטוס, כתובת הדף. הסיסמה `k` לא נכתבת לגיליון.

**מה נדחה:**
- ליד בלי סימון הסכמה.
- טלפון שאינו 9 עד 15 ספרות.
- סיסמה שגויה, כשהוגדרה.
- **הגבלות בצד השרת**, שלא תלויות במה שהדפדפן שולח:
  - עד 10 לידים בדקה ועד 120 בשעה לכל הסקריפט.
  - עד 3 לידים לאותו טלפון בשעה.
  - עד 5 לידים לאותו session ב-10 דקות.

שינוי בסקריפט = **Deploy → Manage deployments → Edit → New version**. כך ה-URL נשאר אותו URL.

## 3. מספר WhatsApp

היום בפיקסטורה יש מספר דמה, `972500000000`. צריך מספר אמיתי של מי שעונה ללידים, בפורמט בינלאומי בלי + ובלי אפס מוביל (למשל `972521234567`). הוא נכנס ל-`project.json → leads.whatsapp_number`. ההודעה שהרוכש שולח נראית כך (היום, בלי שינוי):

```
שלום, אני מתעניין/ת בפרויקט Rainbow תל אביב, דירה 846.
rainbow|846|<session>
```

השורה השנייה מקשרת את השיחה לאירועים בדשבורד.

**החלטה שלך (אלירן):** אפשר להוסיף שורה שלישית, `viewed:846,857`, שאומרת לאיש המכירות באילו דירות הרוכש צפה. הרוכש רואה את השורה הזו בהודעה שהוא שולח. היום היא **כבויה**. מדליקים אותה ב-`project.json → analytics.whatsapp_viewed_line: true`. בטופס ל-Sheet הרשימה נשלחת תמיד, כי הרוכש לא רואה אותה שם.

## 4. קישורי קמפיין

לכל ערוץ קישור משלו: `https://<הכתובת>/flow.html?project=rainbow&src=fb-oct` (גם `utm_campaign` / `utm_source` נקראים). המקור נשמר לכל ה-session, נכנס לכל אירוע ולכל ליד, ומופיע בדשבורד בטבלת "מקורות".

## מה יוצא מהמכשיר (רק כשהמפתח או ה-URL קיימים)

**ל-PostHog** (רק עם `posthog_key`): שם האירוע, הזמן, ו-`token` (המפתח הציבורי), `distinct_id` (= session_id של הלשונית, לא מזהה קבוע של המכשיר), `$lib`, `$process_person_profile=false`, ומתוך האירוע רק: session_id, project, unit, room, floor, finish, src, dwell_ms, tab, channel, scene, prev, on, page, lang, via, mode, status, units_viewed, stubbed, path, test. **בלי שם, טלפון, מייל, כתובת URL מלאה, referrer, cookie או מזהה מכשיר.** ברמת הרשת, כמו כל בקשה: כתובת IP (נמחקת אם סימנתם Discard client IP data) ו-User-Agent.

**ל-Google Sheet** (רק עם `sheet_endpoint` / `webhook_url`, ורק כשהרוכש שלח טופס עם הסכמה): name, phone, consent, project, unit, floor, price, status, units_viewed, src, session_id, lang, url (כתובת הדף, כולל `sid`/`src`), ts.

**ל-WhatsApp** (רק כשהרוכש לוחץ, והוא שולח בעצמו): הטקסט שלמעלה. שורת `viewed:` נשלחת רק אם הדלקת אותה.

**הדשבורד** פונה ל-PostHog רק אם מילאתם בו Project ID ו-Personal API key.

**סינון ערכים (מהבדיקה העצמאית, T2):** לפני שאירוע נשמר או נשלח, בדפדפן וגם בשרת:
- כל שדה טקסט (room, scene, via, src, tab, finish, prev, page, channel, status, mode, lang, unit, project) חייב להיות מילה קצרה: עד 40 תווים מ-`A-Z a-z 0-9 _ . : -`. ערך אחר מוחלף ב-`other`.
- ערך שנראה כמו טלפון (7 ספרות ומעלה), מייל (`@`) או כתובת אינטרנט נמחק לגמרי.
- כך גם טלפון שהגיע בטעות ל-`room`, או קישור קמפיין כמו `?src=dan0501234567`, לא נשמרים ולא יוצאים.

**ה-sink המקומי (`/api/events` ב-serve.mjs):**
- מקבל רק בקשות עם כותרת `Origin` של אותו שרת. דפדפן שולח אותה תמיד. curl וסקריפטים בלעדיה מקבלים 403.
- עד 16 KB ו-50 אירועים לבקשה.
- עד 60 אירועים בדקה לכל כתובת IP. מעבר לזה האירועים נזרקים בשקט.
- הקובץ `_local/events.jsonl` מפסיק לגדול ב-50 MB.
- **את `_local/` ואת `dashboard.html` לא מפרסמים בכתובת ציבורית.** הם לא נכנסים ל-dist ול-ZIP, ו-`build_zip.mjs` נכשל אם הם מופיעים שם.

**`sid` בכתובת הסיור:** דף הדירה מוסיף לכתובת הסיור את `?sid=<session>`, כדי לקשר בין הסיור לאירועים. היום הסיור יושב על 127.0.0.1, כך שזו בקשה מקומית. **בפרודקשן, כשהסיור יושב בדומיין אחר** (למשל Vercel של habait-98), פתיחת לשונית הסיור היא בקשה חיצונית לדומיין הזה, ומזהה ה-session (אקראי, לא אישי) עובר אליו ב-URL. לכן היא לא נכללת ב-"0 בקשות חיצוניות" של הבדיקה. אם הסיור יעבור לצד שלישי שאינו שלנו, צריך להוריד את `sid` מהכתובת.

**`url` בליד:** הטופס שולח ל-Sheet את כתובת הדף המלאה, כולל `sid` ו-`src`. זה מכוון: כך רואים מאיזה קמפיין הגיע הליד.
