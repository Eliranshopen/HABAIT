# מחקר: ה-Frontend של מערכת ההדמיות, מא' עד ת'
<!-- 2026-11-08 · main session · follows 2026-11-08-visualization-stack-architecture.md and 2026-11-08-backend-plan.md -->

## Context
אלירן (2026-11-08): "אז תעשה גם ל-FRONTEND ממש מא עד ת כל מה שצריך". המחקר צריך להגיע לאותו עומק כמו ה-backend.

מה כבר קיים: בחירת framework (Next.js 16), ספריית 360 (PSV 5) ו-RTL ברמה כללית, ממחקר הסטאק.

ההיקף, לפי מה שאלירן קבע: מערכת ההדמיות בלבד. קונים צופים באופן אנונימי, אין חיוב, ואין התממשקות למערכות של היזם. כלל קבוע: כל מסך חייב לעבוד ב-390 (טלפון) וב-1440 (דסקטופ).

## מה צריך לתכנן
1. **משטחים, מסכים וזרימות:** קונה (עמוד פרויקט, בניין, בחירת דירה, סיור, שינוי עיצוב, שיתוף), יזם (פורטל: העלאה, אישור spec ו-trace, מעקב, פרסום), embed.
2. **ארכיטקטורת אפליקציה:** אסטרטגיית רינדור לכל משטח (SSG/ISR/SSR/PPR/Cache Components), routing, ניהול state, טפסים, data fetching מה-backend.
3. **הסיור:** מבנה `<habait-tour>`, API של הרכיב, מעברים, hotspots, שינוי עיצוב, gyroscope, תקשורת עם האתר המארח, embed (Web Component מול iframe, CSP).
4. **ביצועים בטלפון:** תקציב משקל וזמן, אריחי פנורמה, מגבלות WebGL ב-iOS Safari, GLB של בית הבובות (Draco/Meshopt/KTX2), Core Web Vitals.
5. **Design system:** tokens קיימים → Tailwind v4, רכיבים (shadcn RTL), טיפוגרפיה עברית, מצב כהה.
6. **i18n ו-RTL:** עברית ואנגלית, ספרייה, bidi.
7. **נגישות:** תקן ישראלי (IS 5568 / WCAG), הצהרת נגישות, נגישות של סיור 360.
8. **איכות:** בדיקות (unit, ‏e2e, ‏visual regression, בדיקות במכשירים), ניטור שגיאות ואנליטיקס.
9. **מבנה קוד:** `apps/web`, ‏`packages/viewer`, ‏`packages/ui`.
10. **מסלול מעבר** מהקוד הקיים (`platform/`, ‏`tour360/`, ‏`studio-web/`).

2. **מחקר A:** ארכיטקטורת אפליקציה, design system, i18n, נגישות, בדיקות.
