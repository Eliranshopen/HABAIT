## Rules
1. One worktree per parallel session, flat folder name under `.wt/`, created only by `/worktree-ops`.
2. A worktree is registered the moment it is created (its purpose, deploy target and record) — an unregistered directory under `.wt/` is an orphan and is reported, never removed.
3. Every removal is Eliran's explicit act, the authorizing line quoted verbatim in the run, naming the path (D11). Junction-bearing shells are removed junction-first; never `rm -rf` a directory that may hold a junction into a live repo.
4. Never run `npm` through a junction; never open `_env-backups/` (a secrets question, `SECRETS-LEDGER.md` §2).
5. Closing a branch = archive tag + push, never delete (R-ORG-2).
6. The pinned identity is checked at worktree creation, not at push time.
7. **R7 — the junction-safe removal procedure** of the previous harness was not transferred. `/worktree-ops` carries the operational steps; Eliran re-ratifies the written procedure here before the first removal (`OWED-005`).
8. **One worktree per thing worked on (Eliran, 2026-11-03; root `CLAUDE.md` §8.7).** Not only per parallel session: every board, task, fix or experiment gets its own `.wt/<name>` off the repo it belongs to, and the main checkout stays on `main`. Register in `worktrees.json` on creation; close = rebase on `main` → `--ff-only` merge from the main checkout → `archive/<name>` tag; removal stays Eliran's act. Memory and register rows are written in the main checkout, never in a worktree's copy. `.wt/` is gitignored by the harness repo except `.wt/CLAUDE.md`.
